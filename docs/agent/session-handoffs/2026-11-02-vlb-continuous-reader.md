# VLB continuous reader and citation routing

## Base and requested behavior

The branch starts from current `main`, commit
`ef6a586c5d13733537480048924de1776662c70c`, which already includes PR #35.
The user requested continuous page scrolling, removal of the homepage VLB
navigation item, and inline dictionary references that open the new reader at
the relevant OCR passage when one can be selected.

## Inline citation contract

The root dictionary's VLB links now look like:

```text
/nhe-enga/vlb/?volume=I&page=17&mode=continuous&focus=auto&entry=7210&citation_pos=86
```

- `entry` is the row in the pinned dictionary snapshot, including rows with no
  legacy `i` field.
- `citation_pos` is the zero-based Unicode code-point position of the clicked
  numeric page token in the original `d` field. Resolve it against the page's
  citation interval: `citation_start <= citation_pos < citation_end`.
- `linkSources` receives the untouched definition separately from its
  formatted HTML. No citation ID is fabricated from markup offsets.
- The locator position naturally handles inherited spans with leading spaces,
  lists, ranges, and repeated references to the same page. Two `îepé` examples
  at row 5056 both cite I17 but retain their distinct source occurrences.
- Mode and focus request a reader behavior; neither changes the review status
  of a source association. OCR target selection is delegated to
  `vlb/citation-targets.js`.

The homepage has no VLB navigation item. The reader remains accessible through
inline references and its direct URL. Existing scan-only URLs remain valid.

## Formatter copies and ambiguity

The existing dictionary formatter repeats some source examples with their
citations. There are **6,164 raw valid page links** but **6,323 displayed
copies**. Linking before formatting was tested and rejected: it changed
existing quote structures and dropped some links.

Instead, numeric locators are matched by printed volume/page to their untouched
source positions. A unique original locator can serve multiple displayed
copies. When original and displayed counts agree, source order is preserved.
When several originals share a page and rendering changes that count, the
link omits `citation_pos` and the reader must ask for a choice before focusing.

This yields **6,225 precise displayed links** and **98 ambiguous copies across
29 entry/page groups**. For example, `aîa` (row 2502) has two original II64
references but three displayed copies. Selecting the first occurrence would
invent an identity; the fallback deliberately avoids that.

## Continuous reading and line targeting

`mode=continuous` uses lazy ordered stacks inside the existing scan and text
panes. A user scroll tracks the current page and approximate within-page
position, synchronizes the other pane, and replaces the URL without appending
history entries. Earlier pages are inserted with explicit viewport-anchor
preservation. Split paragraphs retain page-scoped DOM IDs and OCR boxes.

The page view remains available through the Leitura selector. Nearby scan
retention follows reading order, including the I154→II7 boundary; distant
images release their `src`, while already-read text remains available. A
successful optimized-image→PNG fallback survives image unloading/reloading.
Resize handling preserves the selected source or current reading position.

`citation-targets.js` offers 1,461 navigable page-membership targets in the
pinned data: 2 assisted reviews and 1,459 still-proposed targets. Proposed jumps
require one distinct form-evidence candidate, unique rank, aligned OCR, and
either supporting context or a matching OCR form; repeated forms elsewhere on
the page are rejected. 1,372 proposed targets narrow to form-bearing OCR runs;
the remaining 87 use the supported paragraph's aligned runs. The UI displays
the review status and never changes the underlying association data.

## Deployment and checks

`scripts/build_pages.sh` publishes `vlb/citation-targets.js` alongside the
reader. The dictionary-formatting workflow includes
`tests/vlb_citation_targets.test.cjs` in its trigger, sparse checkout and run
steps. Existing `vlb/` offline grouping already covers this helper.

Focused checks:

```sh
node --test tests/vlb_dictionary_links.test.cjs
python tests/test_vlb_citation_inventory.py
node --test tests/vlb_citation_targets.test.cjs
bash -n scripts/build_pages.sh
```

The linker regression checks all original source spans against the audited
citation data, exercises production formatted HTML across the corpus, verifies
inherited references and supplementary Unicode characters, and preserves
every source token. The continuous reader's browser tests cover its scrolling,
selection, history and source-focus behavior. No dictionary or VLB source
snapshots are regenerated by the routing change.

The browser harness also serves the real homepage and `neologisms.csv`, follows
its actual inline citation URL, and checks the selected form-bearing OCR run.
It verifies continuous loading in both directions, preserved prepend anchors,
bidirectional page synchronization, history behavior, split IDs, ambiguous
same-page references, mode switching and mobile layout. Continuous screenshots
use viewport capture: the locally available Chrome131/Playwright combination
resizes nested scrollports during full-page capture, which changes the displayed
reading position. Painted-page geometry is asserted before capture.
